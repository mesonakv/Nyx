1. 项目定位
Terra 是一款基于 NyxEngine 的球体地球模拟器级别游戏。玩家作为一个可交互实体，在真实的球体地球上自由行动、探索、战斗、交易、体验。

Terra 的核心不是任务、不是剧情、不是关卡。地球本身就是内容。

1.1 一句话定义
一个在真实球体地球上的、第一人称步行优先的、高自由度、体验为主的巨型 RPG。气象、洋流、昼夜、季节在全球范围内持续演化。玩家是世界的过客，不是造物主。

1.2 核心特征
特征	说明
球体地球	完整球体模型，玩家可在球面上任意移动，无地图边界
地球尺度	真实地形数据，全球可探索
步行优先	核心体验是第一人称步行、跑酷、战斗
多载具预留	架构支持帆船、飞行、地面载具，按优先级逐步实现
自洽模拟	全球气象、洋流、昼夜、季节系统
体验为主	非沙盒，地形不可修改，玩家是世界过客
高自由度 RPG	角色成长、技能、经济，无强制任务
完全 PvP	玩家之间可自由攻击，规则由服务器配置决定
多人预留	单机优先，架构为几百人同时在线做准备
1.3 非目标
明确不做的事：

政治系统

玩家间市场（经济参考《猎杀对决》，非塔科夫跳蚤市场）

地形修改 / 建造 / 破坏

关卡编辑器

手工精修的全城建模（初始阶段不做，未来可能做少数热点）

顶级画质（不追求 3A，追求极致优化）

剧情 / 对话 / 任务文本

1.4 尺度感：A、B、C 三种视角
Terra 的视觉核心是从地面到太空的连续体验：

视角	玩家位置	视觉特征	技术基础
A 地面	地表	地平线渐隐，天空渐变	球面地形 + 大气散射
B 高空	10~100km	地平线明显弯曲	球面几何 + 大坐标
C 太空	100km+	完整蓝色星球	完整球体渲染
C 是基础，A 和 B 是它的自然结果。 采用完整球体架构，三种视角自动一致，不需要为每种视角做特殊处理。

2. 与 NyxEngine 的关系
2.1 引擎定位

2.3 模块化原则
运行时可选：不启用的模块不初始化、不占用内存

接口稳定：模块间接口一旦定义，不因内部实现改变

训练器优先：Terra 不得拖累训练器的延迟和性能

WorldState 分离：所有游戏状态集中在 WorldState，为网络做准备

3. 球体地球基础
3.1 坐标系统：ECEF
采用 ECEF（Earth-Centered, Earth-Fixed）坐标系。

原点在地心

Z 轴指向北极

X 轴指向本初子午线

Y 轴与 X、Z 构成右手系

所有世界坐标用 double（64 位） 存储

渲染时的处理：

相机位置附近的局部原点从所有坐标中减去

得到 32 位浮点局部坐标

保证近距离精度，避免抖动

重力方向：

不再是固定的 (0, -1, 0)

而是 -normalize(位置)（朝地心方向）

物理系统需要感知这一点

玩家的"上/下"相对于所在位置的局部方向

为什么这是唯一正确方案：

平面坐标模拟球体会在所有尺度出现问题（飞行、地平线、大气、重力）

改成 ECEF 是一旦架构定下就难以回头的决策

训练器不受影响（它只在一个小区域）

Terra 从一开始就必须是对的形式

3.2 瓦片系统
瓦片 = 球体表面的一块。

全球地形被切成瓦片，按需加载。玩家走到哪，加载哪附近的瓦片。

瓦片不是平面矩形，是球面四边形。

为避免极点处退化，采用以下之一：

Cube Sphere：把立方体投影到球面

S2 Geometry：Google 的方案，球面四叉树

多分辨率分层（LOD 金字塔）：

层级	分辨率	用途	预估大小
L0	1km	全球背景	~65 GB
L1	100m	区域过渡	~6.5 TB
L2	30m	城市/热门区域	按需生成
起步策略： 先做 L0（1km），验证整个管线后再升级。

瓦片格式（待定）：

候选方案：

自定义 .nyxtile 格式（高度图 + 材质索引 + 碰撞信息 + LOD 元数据）

参考 Quantized-Mesh（Cesium 标准）

混合方案

决策依据：未来的流式加载系统复杂度、磁盘占用、加载速度。

3.3 大坐标系统
问题： 32 位浮点数在地球尺度下精度不足，会产生可见抖动。

方案： 原点平移（Origin Shifting）

渲染原点始终跟随相机

世界坐标使用 64 位精度存储

渲染时减去原点，得到局部 32 位坐标

未来可升级为双精度分层坐标

精度参考：

地球半径：6371 km

32 位浮点在 10km 外开始抖动

64 位浮点在 10000km 外才开始抖动

4. 地形数据管线
4.1 数据源
Copernicus DEM：30m 分辨率，全球覆盖，免费，质量最优。

4.2 处理流程
text
原始 DEM 数据（.tif / .hgt）
    ↓ 离线预处理管线
分层瓦片（多分辨率金字塔）
    ↓ 存储到 SSD
运行时按需加载
4.3 分层策略
全球分三层：

A 级景点（迈阿密、纽约、东京等）：手工精修 + 高精度

B 级区域（海岸线、主要城市周边）：自动生成 + 中精度

C 级背景（内陆、海洋、极地）：自动生成 + 低精度

初始阶段： 全部 C 级。不手工精修任何城市。

未来： 按玩家热度依次升级 B 级和 A 级。

4.4 存储策略
一次性预计算所有瓦片

存储到本地 SSD

运行时只读取，不生成

地形是静态资产

4.5 不可修改
Terra 的地形不可修改。 玩家不能挖地、建房、改变地貌。

简化存档系统

简化网络同步

简化物理

让游戏专注"体验"而非"创造"

5. 流式加载系统
5.1 设计原则
参考 Minecraft 区块加载机制，但适配球体地形：

全局状态流：气象、时间、季节等轻量数据，后台持续加载

空间数据流：地形、建筑等重量数据，按玩家位置加载

5.2 两级加载
弱加载（背景层）

低精度地形（L0）

区域元数据（地貌、气候）

状态流缓存

粗略碰撞

强加载（前景层）

高精度地形（L1、L2）

植被、建筑、道路

精细碰撞

局部光照、局部天气效果

5.3 加载半径（按载具）
载具	强加载	弱加载
步行	500m	5km
帆船	2~5km	50km
飞机	20~50km	200km
5.4 瓦片切换
基于相机位置和朝向决定加载优先级

后台线程异步加载

磁盘缓存 + 内存缓存

无缝切换（不卡顿、不闪烁）

6. 大气与天空系统
6.1 分层设计
层级	内容	优先级
L0	大气散射（Rayleigh + Mie）	必须
L1	高层云（卷云）	高
L2	中层云（层积云）	中
L3	低层云（积雨云）	中
L4	极光	低
L5	降水（雨、雪、冰雹）	中
L6	闪电事件	低
6.2 球面大气散射
问题： 从太空看地球边缘是蓝色光环，从地面看是头顶渐变。这两者必须一致。

方案： 球形大气模型

大气层是球壳

光线穿过大气时按物理路径积分

输出两种视角的一致结果

起步方案： Preetham 或 Hosek-Wilkie 解析模型（纯数学，零纹理）

未来方案： 屏幕空间 raymarching（可选，高画质档位）

6.3 昼夜与季节
太阳方向随经纬度、日期、时间变化

采用真实天文公式（不必高精度，但要正确趋势）

极昼极夜在极地正确出现

季节影响全球太阳辐射分布

6.4 程序化天空
非贴图、非建模。 所有天空元素由程序生成：

大气散射：物理公式

云：FBM 噪声 + 分层参数

极光：屏幕空间噪声带 + 垂直渐变

星空：程序化星点 + 银河带

噪声源： 预计算 2D/3D 噪声纹理，一次性生成，shader 采样。

7. 气象模拟
7.1 设计目标
模拟的深度由玩家决策需要决定，而非画面需要。

帆船要依赖风向；飞行要依赖气流；狩猎要依赖天气。玩家读气象场做决策，这个游戏就活了。

7.2 分层架构
Layer 0：全球气象场（服务器/离线计算）

网格分辨率：1° × 1°（约 110km）

更新频率：每 10 分钟至 1 小时

数据：风速、风向、气压、温度、湿度

模型：简化大气环流

太阳辐射

科里奥利力

地形阻挡

海洋热容

Layer 1：区域天气（客户端）

根据全球场插值出局部天气

加入地形影响（山谷风、海陆风）

决定降水、云量、能见度

Layer 2：局部效果（客户端）

雨滴、雪花、闪电等视觉表现

不影响模拟，只负责渲染

7.3 洋流
类似气象，但是海洋的流动

影响帆船航行

影响海洋温度，进而影响气象

7.4 与玩法耦合
帆船航行：

读全球风场，判断风向、风力

规划航线时考虑季节、信风带、洋流

遭遇风暴时需要决策（绕行 / 穿过 / 等待）

飞行：

读气流、云层

影响飞行难度

步行：

读局部天气

影响移动速度、能见度、舒适度

8. 玩法系统
8.1 核心循环
text
玩家在世界中自由行动
    ↓
观察环境（天气、地形、势力）
    ↓
做出决策（去哪、带什么、何时出发）
    ↓
执行行动（移动、战斗、交易）
    ↓
获得反馈（经验、物品、货币、信息）
    ↓
回到观察
没有强制任务。 地球本身就是目标。

8.2 角色系统
等级： 缓慢成长，基于行为而非任务。

技能（参考《逃离塔科夫》）：

按使用频率自然成长

但避免"老玩家碾压新玩家"的 PvP 失衡

倾向奖励"探索深度"而非"战斗强度"

装备（参考《猎杀对决》）：

玩家与 NPC 交易，无玩家间市场

装备有损失感（死亡后丢失）

8.3 战斗系统
第一人称射击，手感参考塔科夫。

起步：3~5 种武器（手枪、步枪、霰弹枪、狙击枪、近战）

深度优先于广度：同一把枪有 10~20 个改装件

弹道、后坐力、风偏、下坠真实模拟

子弹规则：

子弹只在加载范围内存在

超出加载范围后消失（不追踪、不命中）

玩家可以互相攻击

攻击规则由服务器配置文件决定（未来）

这意味着：

单机模式下，子弹就是本地物理

多人模式下，服务器配置决定谁能攻击谁、在什么条件下攻击

可以做出"和平区"、"战区"、"自定义规则"等

8.4 载具系统
原则：要么全做，要么不做。

架构预留：

帆船：依赖风场、洋流、水面

飞行：依赖大气、高度、空气动力学

地面载具：依赖地形、碰撞

实现顺序： 待定（步行优先）

8.5 经济系统
第一版： 直接买卖（参考《猎杀对决》）

玩家与 NPC 交易

固定价格，无市场波动

货币用于购买武器、消耗品、载具

未来： 可考虑动态价格、区域差异。

9. WorldState 架构
9.1 核心概念
WorldState 是 Terra 所有游戏状态的唯一容器。 从第一天就设计，为网络做准备。

9.2 单机模式
text
Input → GameLogic → WorldState → Renderer
游戏逻辑读写 WorldState，渲染器读 WorldState 渲染。不直接互相调用。

9.3 多人模式（未来）
text
Input → GameLogic → WorldState → Renderer
                     ↓
                  NetworkSync → Server
服务器权威，客户端预测。玩家动作通过 NetworkSync 上传，服务器确认后广播。

9.4 WorldState 内容
玩家实体（位置、朝向、生命值、物品栏）

世界实体（NPC、载具、可交互物体）

环境状态（时间、天气、事件）

交互事件（交易、聊天、战斗）

9.5 设计原则
所有状态有单一权威来源概念

所有可能同步的对象有唯一 ID

时间系统是确定的（相同输入产生相同结果）

随机数有种子（可复现）

9.6 好处
未来加网络时，不需要重构游戏逻辑

单人模式行为可复现（对调试、录制、回放有帮助）

10. 视觉规范
10.1 风格定位
介于镜之边缘与 CS2 之间，可调。

训练器：偏 CS2（干净、克制、目标清晰）

Terra：偏镜之边缘（色块、硬阴影、氛围感）

10.2 PrismSpectra 材质系统
Nyx 的视觉核心，适用于玻璃、珠光、金属、油墨：

菲涅尔：正面弱反射，斜角强反射

干净反射：清晰不模糊

清晰折射：透过玻璃的目标依然锐利

色散：高光边缘极淡的蓝紫粉偏移

微泛光：高光周围极克制的辉光

Terra 中的应用：

水面：干净反射 + 清晰折射

玻璃建筑：菲涅尔 + 色散

金属表面：干净反射

冰面 / 雪地：克制泛光

10.3 性能档位
档位	目标	适用场景
训练器	1000+ FPS	竞技
Terra 探索	200+ FPS	日常游玩
Terra 氛围	100+ FPS	截图、欣赏
Terra 第一章	60+ FPS	全球地形展示
11. 网络架构
11.1 定位
单机优先：第一版纯单机

多人预留：架构为几百人同时在线做准备

服务器轻量：模拟主要在客户端，服务器负责同步和持久化

11.2 设计原则
网络代码从第一天就在架构中

所有状态有明确的权威来源

所有预测有回滚机制

11.3 架构设想
服务器职责：

玩家位置同步

持久化状态

全局事件广播

气象场计算与分发

攻击规则配置

客户端职责：

局部渲染

玩家周围的气象插值

物理模拟

预测和回滚

同步策略：

玩家位置：高频同步

世界状态：低频同步

气象场：定期拉取

11.4 子弹与攻击规则
子弹只在加载范围内存在

超出加载范围后消失

攻击规则由服务器配置文件决定

支持"和平区"、"战区"、"自定义规则"

12. 第一章：第一个可玩版本
12.1 定义
"作品的第一章"，不是技术 demo。

目标不是"能飞起来"，而是"第一次看到地球时，感觉对了"。

12.2 范围
必须有：

全球 1km 分辨率地形

流式加载系统

自由相机（无碰撞，可乱飞）

ECEF 大坐标系统

球面大气散射

基础水面

昼夜循环

A、B、C 三种视角自然一致

可以没有：

材质细节（纯色或简单着色即可）

植被

建筑

载具

玩家角色

天气系统

多人

12.3 成功标准
玩家截图发朋友圈

帧率稳定 60+（第一章不要求极限性能）

从太空到地面的过渡流畅无卡顿

大气散射在三种视角下视觉一致

12.4 技术验证点
Copernicus 数据能否正确转换

1km 瓦片能否流畅加载

ECEF 坐标是否解决抖动

球面大气散射在三种视角下是否正确

长时间飞行（跨大陆）是否稳定

内存占用是否可控

16. 一句话总结
Terra 是一个在真实球体地球上的、第一人称步行优先的、高自由度、体验为主的巨型 RPG。它是自洽运转的星球，玩家是过客，不是造物主。它建立在模块化的 NyxEngine 之上，训练器是它的第一个应用，Terra 是它的最终愿景。
