1. 项目概述
Nyx 是一个模块化专用游戏引擎，同时支撑两个平行应用：

Nyx Trainer：第一人称 FPS 瞄准训练器

Terra：球体地球模拟器级别的巨型 RPG

Nyx 不是通用引擎，不做"什么游戏都能做"的承诺。它为这两个应用服务，并为它们做足基础设施，使得游戏开发阶段尽量不改引擎。

1.1 核心设计理念
理念	含义
专用而非通用	只为两个已知应用服务，不做无意义抽象
模块化	核心层 + 应用层，编译可选，互不拖累
C++ 但 C 风格	禁用异常、RTTI，无隐藏开销
配置驱动	一切可调参数集中在 EngineConfig
克制	不做不需要的功能
一次建好	引擎基础设施一次做完，游戏阶段不改引擎
训练器优先	训练器是第一个产品，Terra 是最终愿景
1.2 工程约束
编译器：MSVC（Windows 首选）

C++ 标准：C++17

构建系统：CMake 4.4+

不使用异常、RTTI

不使用第三方重量级库（除 SDL2、Vulkan、ImGui、glm 外）

线程安全：核心系统默认线程安全

零分配热路径：每帧关键路径不分配堆内存

3. 核心模块
3.1 VulkanContext
职责：Vulkan 实例、设备、swapchain、render pass、命令池。

关键特性：

三种窗口模式（Windowed / Borderless / Exclusive Fullscreen）

多帧并行（MAX_FRAMES_IN_FLIGHT = 2）

swapchain 重建安全

MSAA 支持（1/2/4/8）

Present mode 自动查询

3.2 Renderer
职责：主渲染管线，mesh 上传，命令缓冲录制。

关键接口：

cpp
void DrawFrame(VulkanContext& ctx, const FrameData& frame);
void UploadMeshData(VulkanContext& ctx, const void* vertexData, size_t vertexBytes,
                    VkBuffer& outBuffer, VkDeviceMemory& outMemory);
Push constant 布局：

cpp
struct ObjectPushData {
    glm::mat4 model;      // 64 字节
    glm::vec4 color;      // 16
    glm::vec4 material;   // 16: x=metallic, y=roughness, z=emissive, w=isScreenSpace
};
// 共 96 字节，留 32 字节余量给 PrismSpectra
Uniform buffer 布局（每帧）：

cpp
struct FrameUniforms {
    glm::mat4 viewProj;
    glm::vec4 cameraPos;
    glm::vec4 lightDirAndIntensity;
    glm::vec4 lightColor;
    glm::vec4 ambientColor;
};
3.3 InputSystem
职责：SDL 事件采集，鼠标/键盘状态缓存。

设计原则：只采集，不解释。不知道 F1 是切编辑器。

关键接口：

cpp
float GetMouseDeltaX() const;
float GetMouseDeltaY() const;
bool IsKeyDown(SDL_Scancode key) const;      // 按住
bool WasKeyPressed(SDL_Scancode key) const;  // 本帧刚按下
bool WasKeyReleased(SDL_Scancode key) const; // 本帧刚释放
void SetMouseCaptured(bool captured);
bool ShouldQuit() const;
3.4 LightingSystem
职责：从 EngineConfig.lighting 计算光照数据。

输出：

cpp
struct LightingData {
    glm::vec3 lightDir;
    glm::vec3 lightColor;
    float lightIntensity;
    glm::vec3 ambientColor;
    glm::vec4 skyTopColor;
    glm::vec4 skyBottomColor;
};
时间语义：timeOfDay ∈ [0, 1]

0.00 午夜

0.25 日出

0.50 正午

0.75 日落

3.5 EngineConfig
职责：集中管理引擎层可调参数。

cpp
struct EngineConfig {
    LightingConfig lighting;
    CameraConfig camera;
    RenderConfig render;
};
3.6 EditorPanel
职责：编辑器 UI 框架，容器 + 子面板。

六个子面板：Camera / Material / TargetMovement / DisplaySettings / Lighting / Performance

4. 基础设施模块（批次 1 + 2）
4.1 Logger
职责：统一日志输出。

分级：Trace / Debug / Info / Warn / Error / Fatal

用法：

cpp
NYX_LOG_INFO("GPU: %s", props.deviceName);
NYX_LOG_ERROR("Failed: %d", errorCode);
NYX_LOG_FATAL("Cannot recover");  // 记录后 abort
特性：

线程安全

时间戳 + 级别 + 文件:行号

输出到控制台、文件、VS 输出窗口

Release 下 Trace/Debug 编译期裁剪

4.2 Memory
职责：分配追踪，泄漏检测。

用法：

cpp
Foo* f = NYX_NEW(Foo, "Render");
NYX_DELETE(Foo, f);

void* buf = NYX_ALLOC(1024, "Temp");
NYX_FREE(buf);
特性：

Debug 模式追踪每次分配（大小、tag、文件、行号）

Shutdown 时报告未释放的分配

按 tag 统计

4.3 NyxMath
职责：glm 薄封装 + 项目工具函数。

用法：

cpp
#include "NyxEngine/Core/NyxMath.h"

using namespace nyx;

Vec3 pos = {1.0f, 2.0f, 3.0f};
float angle = DegToRad(45.0f);
Vec3 dir = Normalize(pos);
Mat4 mvp = Perspective(fov, aspect, 0.1f, 100.0f) * LookAt(eye, center, up);
重要提示：任何 include glm 的文件，都要先 include <cmath>。或者直接 include NyxMath.h，它已经处理好了。

4.4 FileSystem
职责：文件读写、路径处理。

用法：

cpp
std::string text = FileSystem::ReadText("config.json");
FileSystem::WriteText("output.txt", "hello");

std::string path = FileSystem::Join(FileSystem::GetExecutableDir(), "config.json");
4.5 Platform
职责：隔离操作系统 API。

用法：

cpp
Platform::Initialize();
uint64_t t = Platform::GetTimerNanos();
Platform::SleepMs(16);
uint32_t cores = Platform::GetCPUCoreCount();
4.6 EventBus
职责：类型安全的事件总线。

用法：

cpp
struct TimeChangedEvent { float timeOfDay; };

auto handle = EventBus::Subscribe<TimeChangedEvent>([](const TimeChangedEvent& e) {
    NYX_LOG_INFO("time changed to %f", e.timeOfDay);
});

EventBus::Emit(TimeChangedEvent{0.5f});
EventBus::Unsubscribe(handle);
特性：

同步派发

Copy-on-write 订阅表

Emit 时对订阅列表做快照，回调内可以安全地订阅/取消

4.7 JobSystem
职责：线程池，异步任务。

用法：

cpp
JobSystem jobs;
jobs.Initialize();     // 默认 CPU 核心数 - 1

jobs.Submit([]() {
    // 在后台线程执行
});

jobs.WaitAll();        // 等待所有任务完成
jobs.Shutdown();
限制：不支持任务依赖（DAG）、优先级、取消。

4.8 JsonValue
职责：JSON 解析和序列化。

用法：

cpp
// 构建
JsonValue root;
root["name"] = "NyxEngine";
root["version"] = 1;
root["lighting"]["timeOfDay"] = 0.5f;
root["tags"].Push("engine");
std::string text = root.ToString(true);  // pretty print

// 解析
std::string err;
JsonValue parsed = JsonValue::Parse(text, &err);
if (!err.empty()) { /* 错误 */ }
float t = parsed["lighting"]["timeOfDay"].AsFloat(0.5f);
支持：Null / Bool / Int / Float / String / Array / Object
不支持：注释、NaN、Infinity、BMP 外的 Unicode 转义

5. Resource 系统（优化 E）
5.1 MeshData
职责：CPU 端网格数据。

cpp
struct MeshVertex {
    glm::vec3 position;  // 12
    glm::vec3 normal;    // 12
    glm::vec3 color;     // 12
};                       // 共 36 字节

struct MeshData {
    std::vector<MeshVertex> vertices;
    std::vector<uint32_t> indices;
};
顶点布局和 Renderer 的 vertex input 一致（stride 36，3 个 attribute）。

5.2 Mesh
职责：网格资源，持有 MeshData。

cpp
class Mesh {
    const MeshData& GetData() const;
    bool IsValid() const;
};
5.3 MeshLoader
职责：从 .obj 加载网格。

支持的 obj 子集：

v x y z [r g b]：顶点位置（可选 RGB）

vn x y z：顶点法线

f v1 v2 v3 ...：面（支持 v、v//vn、v/vt/vn）

不支持：vt（纹理坐标）、mtl、o、g、s

5.4 ResourceManager
职责：资源缓存 + 引用计数。

用法：

cpp
ResourceManager res;
auto mesh = res.LoadMesh("assets/cube.obj");
if (mesh) {
    const MeshData& data = mesh->GetData();
    // ...
}
特性：按路径缓存，shared_ptr 引用计数。

7. 关键设计决策
7.1 容器策略
混合：

使用 std::vector、std::string 等标准容器

通过自定义 allocator 控制分配

不自己写 vector、string

7.2 反射策略
轻反射：宏或代码生成，支持序列化 + 编辑器自动 UI。（未来）

7.3 JobSystem 策略
先做简单线程池：一个任务队列，N 个 worker 线程，不支持任务依赖。

7.4 音频后端
miniaudio（待建）：单头文件、跨平台、低延迟。

7.5 坐标系统
训练器：局部平面坐标

Terra：ECEF 球体坐标（未来）

两者通过接口切换，核心层不假设坐标类型。

7.6 WorldState
训练器：不使用 WorldState

Terra：使用 WorldState（未来）

WorldState 是可选层，不是强制中介。

8. 工程哲学
8.1 代码风格
C++ 但 C 风格

禁用异常、RTTI

函数名：PascalCase

成员变量：snake_case_（尾部下划线）

常量：kConstantName

宏：NYX_MACRO_NAME

8.2 内存管理
核心系统默认预分配

热路径零分配

使用 Memory 封装（Debug 可追踪）

不用 new / delete，用 NYX_NEW / NYX_DELETE

8.3 错误处理
不使用异常

使用返回码或 assert（Debug）

不可恢复错误 → NYX_LOG_FATAL + abort()

可恢复错误 → 日志 + 返回 false

8.4 日志
统一用 Logger

不用 std::cout / std::cerr（除启动阶段）

8.5 命名空间
核心层使用 nyx::

应用层不加命名空间（或使用独立命名空间）

10.2 PrismSpectra
定位：Nyx 的材质光学质感系统。

技术组件：

菲涅尔：正面弱反射，斜角强反射

干净反射：反射天空和纯色几何体，不模糊

清晰折射：透过玻璃的目标依然锐利，仅轻微偏移

色散：高光边缘极淡的蓝紫粉偏移

微泛光：高光周围极克制的辉光

设计哲学：

克制：粉蓝泛光只在高光边缘出现，且非常轻微

真实之上：物理正确，但更强调干净的视觉体验

可复用：同一套光学规则应用于玻璃、珠光、金属、油墨

实现路径：

底层：标准 PBR（albedo, metallic, roughness, normal）

上层：PrismSpectra（fresnelStrength, dispersion, bloomTint）

两者正交：可以只用 PBR，也可以叠加 PrismSpectra

12. 一句话总结
Nyx 是一个模块化专用引擎，为训练器和 Terra 两个平行应用服务。它一次把引擎基础设施建完，之后游戏开发不改引擎。它克制、干净、专用，为极致优化而生。
