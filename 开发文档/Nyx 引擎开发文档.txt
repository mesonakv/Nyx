1. 项目概述
Nyx 是一个模块化专用游戏引擎，同时支撑两个平行应用：

Nyx Trainer：第一人称 FPS 瞄准训练器

Terra：球体地球模拟器级别的巨型 RPG

Nyx 不是通用引擎，不做"什么游戏都能做"的承诺。它为这两个应用服务，并为它们做足基础设施，使得游戏开发阶段尽量不改引擎。

1.1 核心设计理念
理念	含义
专用而非通用	只为两个已知应用服务，不做无意义抽象
模块化	核心层 + 应用层，编译可选，互不拖累
C++ 但 C 风格	禁用异常、RTTI，无隐藏开销
配置驱动	一切可调参数集中在 EngineConfig
克制	不做不需要的功能
一次建好	引擎基础设施一次做完，游戏阶段不改引擎
训练器优先	训练器是第一个产品，Terra 是最终愿景
1.2 工程约束
编译器：MSVC（Windows 首选）

C++ 标准：C++17

构建系统：CMake

不使用异常、RTTI

不使用第三方重量级库（除 SDL2、Vulkan、ImGui、glm 外）

线程安全：核心系统默认线程安全

零分配热路径：每帧关键路径不分配堆内存

2.3 模块化原则
编译级隔离：应用层模块默认不编译进不相关的二进制

运行时可选：核心层子系统可以按需初始化

核心层保持轻：不为应用层引入不必要的抽象

接口稳定：模块间接口一旦确定，不轻易改变

职责：Vulkan 设备、swapchain、render pass、命令池管理。

5. 关键设计决策
5.1 容器策略
混合：

使用 std::vector、std::string 等标准容器

通过自定义 allocator 控制分配

不自己写 vector、string

理由：STL 成熟、稳定，重复造轮子无收益。自定义分配器满足追踪和优化需求。

5.2 反射策略
轻反射：

宏或代码生成

支持序列化 + 编辑器自动 UI

不做运行时完整类型信息

理由：Config、Resource、Editor 三处受益巨大，成本可控。

5.3 JobSystem 策略
先做简单线程池：

一个任务队列

N 个 worker 线程

不支持任务依赖

理由：Terra 的流式加载会需要更多，但那是 Terra 阶段的事。

5.4 音频后端
miniaudio：

单头文件

跨平台

低延迟

零依赖

理由：符合"C 风格 C++、无第三方库"的工程哲学。

5.5 坐标系统
训练器：局部平面坐标
Terra：ECEF 球体坐标

两者通过接口切换，核心层不假设坐标类型。训练器不知道 ECEF 存在。

5.6 WorldState
训练器：不使用 WorldState，直接操作游戏对象
Terra：使用 WorldState

WorldState 是可选层，不是强制中介。训练器不知道 WorldState 存在。

6. 工程哲学
6.1 代码风格
C++ 但 C 风格

禁用异常、RTTI

函数名：PascalCase

成员变量：snake_case_（尾部下划线）

常量：kConstantName

宏：NYX_MACRO_NAME

6.2 内存管理
核心系统默认预分配

热路径零分配

使用 Memory 封装（Debug 可追踪）

不用 new / delete，用 NYX_NEW / NYX_DELETE

6.3 错误处理
不使用异常

使用返回码或 assert（Debug）

不可恢复错误 → LOG_FATAL + abort()

可恢复错误 → 日志 + 返回 false

6.4 日志
统一用 Logger

不用 std::cout / std::cerr（除启动阶段）

6.5 命名空间
核心层使用 nyx::

应用层不加命名空间（或使用独立命名空间）

10.2 PrismSpectra
定位：Nyx 的材质光学质感系统。

技术组件：

菲涅尔：正面弱反射，斜角强反射

干净反射：反射天空和纯色几何体，不模糊

清晰折射：透过玻璃的目标依然锐利，仅轻微偏移

色散：高光边缘极淡的蓝紫粉偏移

微泛光：高光周围极克制的辉光

设计哲学：

克制：粉蓝泛光只在高光边缘出现，且非常轻微

真实之上：物理正确，但更强调干净的视觉体验

可复用：同一套光学规则应用于玻璃、珠光、金属、油墨

实现路径：

底层：标准 PBR（albedo, metallic, roughness, normal）

上层：PrismSpectra（fresnelStrength, dispersion, bloomTint）

两者正交：可以只用 PBR，也可以叠加 PrismSpectra
