## 一、引擎定位

Nyx 是一个**专用而非通用**的游戏引擎。它不追求跨平台、不追求生态、不追求被其他开发者使用。它只服务一个目标：**用最低的输入延迟、最好的音频质量、最极致的优化，做出 Noriko 和后续项目。**

- **专用**：只为已知应用服务，不做无意义抽象
- **模块化**：核心层 + 应用层，编译可选，互不拖累
- **C++ 但 C 风格**：禁用异常、RTTI，无隐藏开销
- **配置驱动**：一切可调参数集中在 EngineConfig
- **低延迟优先**：输入延迟、音频延迟、帧时间稳定性是三条红线

## 三、核心模块详解

### 3.1 输入系统

**目标**：Windows 上接近极限的输入延迟。

**架构**：
InputSystem
├── SDL 通道（fallback + 编辑器模式）
└── Raw Input 通道（Windows，游戏模式）
└── Win32InputBackend (WM_INPUT)

text

**双通道切换规则**：
- `useRawInput_ && mouseCaptured_` → Raw Input
- 否则 → SDL

**事件历史**：
- 环形缓冲，容量 4096，保留最近 250ms
- 每个事件带纳秒级时间戳
- 用于输入缓冲、连招窗口、精确判定

**已处理的问题**：
- 快速点射丢输入（分表记录 pressed/released）
- 中文输入法吞键（线程级 `ImmDisableIME`）
- 编辑器模式 Raw Input 失效（自动回退 SDL）

**待解决**：
- InputMap（键位映射）
- 独立输入线程（阶段 3）
- 手柄支持（架构预留）

### 3.2 物理系统

**定位**：Layer 1 完整，Layer 2 由角色控制器实现。**不是刚体动力学引擎。**

**支持形状**：
- Sphere（解析射线、解析碰撞）
- Capsule（采样射线、最近点碰撞）
- Box（解析射线、最近点碰撞）

**Broadphase**：
- BruteForceBroadphase（O(N²)，N<200 时零负担）
- 懒删除 + 压缩
- 抽象接口，将来可换 SAP/BVH

**Narrowphase**：
- 6 种形状对全部支持
- Sphere-Sphere / Capsule-Sphere / Sphere-Box / Capsule-Capsule / Capsule-Box
- Ericson 线段对线段算法

**场景查询**：
- Raycast（射线检测）
- Sweep（保守推进，防穿墙）
- Overlap（重叠检测）
- **查询是单向的**：`queryMask` 只表示"我想查哪些层"

**碰撞过滤**：
- `CollisionFilter { category, mask }`
- `CanCollideWith` 用于碰撞对（双向）
- 查询直接用 `category & queryMask`

### 3.3 Debug 可视化

**DebugDraw**：
- 动态顶点缓冲，host visible + coherent
- 每帧 Begin → 若干 Line/Box/Sphere/Capsule/Ray/Cross → 自动上传
- 线段用 `VK_PRIMITIVE_TOPOLOGY_LINE_LIST`
- 深度偏移避免 z-fighting

**用途**：
- 物理形状可视化
- 射线可视化
- 弹幕轨迹、AI 感知范围、Boss 攻击范围

### 3.4 音频时钟

**AudioClock**：
- 纯时间管理，**无音频后端**
- 由外部 `Tick(dt)` 驱动，和渲染帧同步
- 支持播放/暂停/停止/跳转/变速/循环/结束回调
- 秒 + 采样两种时间单位

**将来**：AudioSystem（WASAPI 独占模式）接入，AudioClock 用真实播放位置反推。

## 七、设计原则总结

**做：**
- 只做 Noriko 和已知项目需要的
- 性能可量化、可对比
- 接口清晰、模块独立
- 早发现早修复 bug
- 现在能用就不要等以后

**不做：**
- 通用引擎抽象
- 为"未来可能"做空壳
- 异常、RTTI、隐藏开销
- 热路径堆分配
- 无意义的第三方依赖
