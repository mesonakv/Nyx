1. 项目概述
Nyx 是一个模块化专用游戏引擎，由 NokaNod 开发，为三个应用服务：

Nyx Trainer / Noriko：第一人称节奏射击训练器（由 Noriko 承载）

Nova：球体地球模拟器级别的巨型 RPG

未来项目：任何需要低延迟、高帧率、模块化架构的游戏

Nyx 不是通用引擎，不做"什么游戏都能做"的承诺。它为已知应用服务，为它们做足基础设施，使得游戏开发阶段尽量不改引擎。

1.1 命名体系
名字	角色	说明
NokaNod	工作室	灵感来自诺和诺德（Novo Nordisk）的读音节奏
Nyx	引擎	希腊夜之女神，暗合冷黑 + 亮蓝的视觉身份
Noriko	训练器 / 音游	由训练器改造，引入音游元素
Nova	地球 RPG	原 Terra，早期策略不变，后期扩展多场景
1.2 核心设计理念
理念	含义
专用而非通用	只为已知应用服务，不做无意义抽象
模块化	核心层 + 应用层，编译可选，互不拖累
C++ 但 C 风格	禁用异常、RTTI，无隐藏开销
配置驱动	一切可调参数集中在 EngineConfig
克制	不做不需要的功能
一次建好	引擎基础设施一次做完，游戏阶段不改引擎
低延迟优先	输入延迟 ≤ 5ms，是所有应用的底线
1.3 工程约束
编译器：MSVC（Windows 首选）

C++ 标准：C++17

构建系统：CMake 4.4+

不使用异常、RTTI

不使用第三方重量级库（除 SDL2、Vulkan、ImGui、glm 外）

线程安全：核心系统默认线程安全

零分配热路径：每帧关键路径不分配堆内存

3. 核心模块
3.1 VulkanContext
职责：Vulkan 实例、设备、swapchain、render pass、命令池。

关键特性：

三种窗口模式（Windowed / Borderless / Exclusive Fullscreen）

多帧并行（MAX_FRAMES_IN_FLIGHT = 2）

swapchain 重建安全

MSAA 支持（1/2/4/8）

Present mode 自动查询

接口：

cpp
class VulkanContext {
public:
    void Initialize(SDL_Window*, const DisplaySettings&);
    void Shutdown();
    void RecreateSwapchain(SDL_Window*);
    void DestroySwapchainResources();
    uint32_t FindMemoryType(uint32_t, VkMemoryPropertyFlags);
    VkSampleCountFlagBits GetMSAASamples() const;
};

职责：主渲染管线，mesh 上传，命令缓冲录制。

关键接口：

void UploadMeshData(VulkanContext& ctx, const void* vertexData, size_t vertexBytes,

4. 基础设施模块
4.1 Logger
职责：统一日志输出。

分级：Trace / Debug / Info / Warn / Error / Fatal

用法：

cpp
NYX_LOG_INFO("GPU: %s", props.deviceName);
NYX_LOG_FATAL("Cannot recover");  // 记录后 abort
4.2 Memory
职责：分配追踪，泄漏检测。

用法：

cpp
Foo* f = NYX_NEW(Foo, "Render");
NYX_DELETE(Foo, f);
void* buf = NYX_ALLOC(1024, "Temp");
NYX_FREE(buf);
4.3 NyxMath
职责：glm 薄封装 + 项目工具函数。

重要提示：任何 include glm 的文件，都要先 include <cmath>。或者直接 include NyxMath.h。

4.4 FileSystem
职责：文件读写、路径处理。

4.5 Platform
职责：隔离操作系统 API（计时、睡眠、CPU 核心数、平台信息）。

4.6 EventBus
职责：类型安全的事件总线。

用法：

cpp
struct TimeChangedEvent { float timeOfDay; };
auto handle = EventBus::Subscribe<TimeChangedEvent>([](const TimeChangedEvent& e) {
    NYX_LOG_INFO("time changed to %f", e.timeOfDay);
});
EventBus::Emit(TimeChangedEvent{0.5f});
EventBus::Unsubscribe(handle);
4.7 JobSystem
职责：线程池，异步任务。

用法：

cpp
JobSystem jobs;
jobs.Initialize();
jobs.Submit([]() { /* 后台执行 */ });
jobs.WaitAll();
jobs.Shutdown();
4.8 JsonValue
职责：JSON 解析和序列化。

支持：Null / Bool / Int / Float / String / Array / Object
不支持：注释、NaN、Infinity、BMP 外的 Unicode 转义

6. PrismSpectra（琉光幻彩）
职责：Nyx 的材质光学质感系统。

6.1 五个组件
组件	描述	实现
菲涅尔	正面弱反射，斜角强反射	Schlick 近似
干净反射	反射天空，清晰不模糊	程序化天空采样
清晰折射	透过玻璃的目标依然锐利	屏幕空间 UV 偏移
色散	高光边缘极淡的蓝紫粉偏移	RGB 三通道不同折射率
微泛光	高光周围极克制的辉光	后处理 Bloom
6.2 设计哲学
克制：泛光只在高光边缘出现，且非常轻微

真实之上：物理正确，但更强调干净的视觉体验

可复用：同一套光学规则应用于玻璃、珠光、金属、油墨

6.3 材质参数
cpp
struct Material {
    // 基础 PBR
    glm::vec4 color;
    float metallic;
    float roughness;
    float emissive_strength;
    float opacity;

    // 琉光幻彩
    float fresnelStrength;     // 0 = 自动从 metallic 推导
    float dispersion;          // 0~0.1
    float refractionStrength;  // 0~1
    float bloomTint;           // 0 = 无泛光
};
6.4 实现路线
菲涅尔 + 干净反射（当前）

清晰折射 + 色散

微泛光（后处理 Bloom）

6.5 天空解耦
关键设计：所有需要天空颜色的地方通过 SampleSky(dir, params) 访问。

glsl
// Shaders/sky_sample.glsl
struct SkyParams {
    vec4 topColor;
    vec4 bottomColor;
    vec3 sunDir;
    vec3 sunColor;
    float timeOfDay;
};

vec3 SampleSky(vec3 dir, const SkyParams params);
天空实现可以自由改变（渐变 → 散射 → 云），琉光幻彩不受影响。

8. 工程哲学
8.1 代码风格
C++ 但 C 风格

禁用异常、RTTI

函数名：PascalCase

成员变量：snake_case_（尾部下划线）

常量：kConstantName

宏：NYX_MACRO_NAME

8.2 内存管理
核心系统默认预分配

热路径零分配

使用 Memory 封装

不用 new / delete，用 NYX_NEW / NYX_DELETE

8.3 错误处理
不使用异常

使用返回码或 assert（Debug）

不可恢复错误 → NYX_LOG_FATAL + abort()

可恢复错误 → 日志 + 返回 false

8.4 命名空间
核心层使用 nyx::

应用层不加命名空间（或使用独立命名空间）

9. 关键设计决策
9.1 容器策略
混合：使用 STL 容器 + 自定义 allocator。不自己写 vector、string。

9.2 反射策略
轻反射：宏或代码生成，支持序列化 + 编辑器自动 UI。（未来）

9.3 JobSystem 策略
先做简单线程池：一个任务队列，N 个 worker 线程，不支持任务依赖。

9.4 音频后端
miniaudio：单头文件、跨平台、低延迟。

9.5 坐标系统
Noriko：局部平面坐标

Nova：ECEF 球体坐标（未来）

两者通过接口切换，核心层不假设坐标类型。

9.6 WorldState
Noriko：不使用 WorldState

Nova：使用 WorldState（未来）

WorldState 是可选层，不是强制中介。

Noriko 开发文档
版本 1.0.0
状态：定位明确，待开发
最后更新：2026-09-13

1. 项目定位
Noriko 是一款第一人称节奏射击游戏，由 NokaNod 开发，基于 NyxEngine。

它的核心是训练器 + 音游的叠加：

保留训练器的所有核心能力（瞄准训练、性能统计、低延迟）

叠加音游元素（目标按音乐节奏出现、射击时机影响得分）

新增自动化编曲器（从音频文件自动生成关卡）

1.1 一句话定义
一个用音乐训练枪法的游戏。它既是专业的瞄准训练器，也是一个可玩的节奏射击游戏。

1.2 核心特征
特征	说明
低延迟	输入延迟 ≤ 5ms，继承训练器基因
高帧率	1000+ FPS
双模式	纯训练模式 + 节奏模式
音乐驱动	目标按节拍出现，射击时机影响得分
自动化编曲	从音频文件自动提取节拍，生成关卡
性能统计	命中率、反应时间、节奏准确度
1.3 非目标
不做完整音游（不是 Beat Saber 的替代品）

不做剧情 / 角色 / 故事

不做多人对战

不做手机版（至少第一版不做）

2. 双模式设计
2.1 纯训练模式
继承现有训练器的全部能力。

目标随机出现

目标 4 种移动模式（Static / Linear / SineWave / RandomDirection）

命中检测 + 计分

性能统计（Avg / P99 / StdDev）

材质预设切换

编辑器面板

这个模式的目标用户：FPS 竞技玩家，日常练枪。

2.2 节奏模式
新引入的游戏模式。

加载一首音乐

自动化编曲器提取节拍

目标在节拍点出现

玩家射击时机影响得分

评分机制：

射击时机偏差	评级	得分
< 30ms	Perfect	100
30~60ms	Great	80
60~100ms	Good	60
100~150ms	Bad	30
> 150ms	Miss	0
这个模式的目标用户：音游玩家 + 想要更有趣训练体验的 FPS 玩家。

2.3 模式切换
主菜单选择模式

训练模式不加载音乐

节奏模式需要先选择音乐文件

两个模式共享：渲染管线、输入系统、材质系统、编辑器面板。

3. 自动化编曲器
3.1 定位
不是"完美提取所有音乐信息"，而是"从音乐中提取节拍，生成射击节奏"。

3.2 核心能力
能力	优先级	说明
节拍检测	必须	找到音乐的重拍
节拍强度	高	区分强拍和弱拍
段落划分	中	识别副歌、主歌、桥段
音高提取	低	未来可能用于生成目标高度
音源分离	极低	未来可能
3.3 节拍检测算法
起步方案：能量包络 + 峰值检测

对音频做短时傅里叶变换（STFT）

计算每个频带的能量

用低频能量（kick drum）做节拍候选

峰值检测 → 节拍点

准确率：对流行、电子、摇滚可到 80~90%。

进阶方案：用现成的库

librosa（Python）：成熟，但需要 Python 集成

aubio（C）：轻量，可以集成到 C++

我建议先用 aubio。它是 C 库，可以直接编入 Nyx。

3.4 输出格式
cpp
struct BeatmapLevel {
    std::string audioPath;
    double bpm;
    double offset;          // 第一拍的偏移
    std::vector<Beat> beats;
};

struct Beat {
    double time;            // 秒
    float strength;         // 0~1，强拍或弱拍
    int type;               // 0 = 单点，1 = 连击
};
3.5 目标生成规则
从 Beatmap 生成目标序列。

强拍	1~3	Static	大

弱拍	1	SineWave	小

这样音乐强的地方目标多、简单；音乐弱的地方目标少、难。

3. 球体地球基础
3.1 坐标系统：ECEF
采用 ECEF（Earth-Centered, Earth-Fixed）坐标系。

原点在地心

Z 轴指向北极

X 轴指向本初子午线

所有世界坐标用 double（64 位） 存储

渲染时：相机位置附近的局部原点从所有坐标中减去。

重力方向：-normalize(位置)（朝地心方向）。

为什么这是唯一正确方案：平面坐标模拟球体会在所有尺度出现问题。

3.2 地形分层：球面起伏 + 表面物体
Nova 的世界拆成两层：

第一层：球面起伏（地表）

连续场：f(lat, lon) → height

唯一的、全局的、不可拆分的

第二层：表面物体（物件）

离散实体：树、建筑、机场

可增删、可替换、可独立编辑

这两层的差异，决定了它们必须用两套系统处理。

3.3 地形数据：程序化重建
Nova 不追求 1:1 复刻真实地球，追求"整体正确、局部可控"。

数据源：

数据	来源	大小
海岸线	Natural Earth 1:110m	几 MB
高程分区	ETOPO1（1.8km）	~100MB 压缩
关键特征	手动标注	几 KB
处理流程：

text
真实数据 → 关键特征提取 → 参数化建模 → 程序化细分 → 可调参数 → 最终地形
保留什么，放弃什么：

保留	放弃
七大洲轮廓	城市细节
喜马拉雅高度	街道走向
马里亚纳深度	具体建筑
气象与洋流	河道细节
3.4 地形生成规则
类型	生成规则	海拔范围
高山	脊线 + 分形噪声	2000~8000m
丘陵	平滑噪声	200~1000m
平原	极低噪声	0~200m
高原	平顶 + 边缘峭壁	1000~4000m
大陆架	缓坡	-200~0m
海洋平原	平坦	-3000~-5000m
海沟	狭长深槽	-6000~-11000m
3.5 物件层设计
四种类型：

类型	例子	数据来源	实现方式
自然散布	树、草、石头	程序化分布	实例化渲染
线状设施	道路、河流、电线	样条曲线	沿线生成
面状区域	森林、农田、城区	多边形区域	区域内分布
点状设施	建筑、机场、港口	单独放置	独立模型
3.6 分层手工策略
层级	内容	工作量	覆盖范围
A 级景点	手工精修的城市	1~2 个月/城	1~5 个

未来可以引入玩家投稿：提供编辑器，玩家布置城市，官方审核后加入正式版本。

3.7 球面物件的放置
核心原理：局部切平面。

球面上任意一点 P 有局部坐标系：

text
Up    = normalize(P)
North = (0, 0, 1) 的切向分量
East  = cross(North, Up)
物件存储：

cpp
struct Placement {
    glm::dvec3 ecefPosition;
    float yaw;
    float scale;
    uint32_t modelId;
};
建筑是直的，道路是分段的，地面是连续的。

建筑：50 米宽的曲率偏差 < 0.05 毫米，无需弯曲

道路：每 100~500 米一段，形成测地线

地面：由地形生成器提供的连续高度场
